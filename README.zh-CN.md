# Hibiki · 模型工作台

[English](README.md)

一个基于 [Pi](https://pi.dev) 原生扩展 API 的第三方插件：选择模型、管理自定义供应商／模型，并调整当前会话的 Fast 请求策略。界面以中文为主。

**0.1.8** 保留 0.1.7 已确认的密集首页与添加流程，并允许用户本地覆盖原生／扩展聊天模型的上下文窗口、最大输出及恢复继承。首页仍是一家供应商一行、行内水平窗口与固定搜索／详情、原底部工作区中的交互动作；筛选与手输仍分开。源码交付、安装／加载、GitHub 发布仍是不同步骤；修改仓库不会替已开窗口自动升级。

## 安装与入口

普通 Pi 包只加载一个入口：`extensions/hibiki-models.ts`，不需要构建、快照或源码还原。不要单独加载内部 `extensions/model-pick.ts`，也不要与旧独立模型选择器／Fast 扩展叠装。

本地源码包可使用 `pi install /absolute/path/to/pi-hibiki`；审阅后由你决定安装和重载。本轮不会自动更改现有加载配置。GitHub 安装地址为 `git:github.com/theseussss/pi-hibiki`，但未推送的本地修订不会出现在远端版本中。

已验证的兼容目标为 **Node.js 24、Pi 1.4.0**。共享凭据锁使用对该宿主版本显式校验的兼容适配；遇到未知版本或无法确认的 SDK 存储绑定时，管理写入关闭，不猜测 HOME 或偷偷写另一份配置。

## 日常使用

`/hibiki`、`/models` 打开模型矩阵；`/hibiki manage`、`/hibiki providers` 直接聚焦可见动作；`/hibiki fast`、`/models fast` 打开当前会话策略。`/hibiki status`、`/hibiki help` 提供版本与帮助。

- **首页 Tab / Shift+Tab** 在对象与动作之间切换。方向键移动；Enter 切换模型。光标候选、当前会话、全局默认彼此独立。
- **Alt+数字执行可见编号动作**：1 收藏，2 编辑／查看，3 完整检查，4 默认，5／6 调序，7 添加模型，8 移除确认，9 新供应商，0 已移除项目。普通数字仍可输入。
- 供应商使用自己的动作模板；不适用的编号不转给其他动作。两次刻意的边界 ← 进入供应商列，→ 返回模型区。
- **任务页不强制 Tab 切区**：方向键可连续经过字段、列表和按钮；Tab 是普通控件遍历。候选／已选可用 ←→ 切换；跨查询保留勾选，Enter 选择或调整参数。
- 保留 Alt+N/X/E/V/D、Alt+方向键、Alt+Z 撤销、Alt+L 显式定位、Alt+T 六套配色、Alt+M/F6 动作入口、F1/Alt+H 帮助。保存不偷偷清查询、定位新增项或切模型。
- 底部动作按窗口宽度增加列数，同宽度下状态不挪按钮。首页矩阵保持一供应商一行、中间省略、行内水平窗口和 `‹`／`+N`；只有中间供应商行分页，标题／搜索／详情／底部操作固定可见。不是逐行撑满或把供应商拆成多行长列表。窄屏／短屏保留滚动、阅读检查和键盘路径。

Ctrl+L 与 Pi 原生模型选择器可能冲突。如需交给 Hibiki，可将 `"app.model.select": []` 合并进现有 `keybindings.json`；不要整份覆盖。不改快捷键也能使用上述命令。

## 添加与检查

新供应商的主路径是：

```text
名称／地址／接口／遮蔽 Key
  → 确认目标并读取本家清单，或手输 ID
  → 搜索／多选／调整参数
  → 确认检查范围，或跳过检查看参考
  → 分项进度、取消及完整报告
  → 独立最终确认保存
  → 回原矩阵
```

- 添加已有供应商的模型时，先带入该连接，不自动联网。尚未读取、读取成功为空、返回项已全添加、读取失败／取消、筛选无匹配分别说明，不把它们一律显示为“本家模型 0”。只有存在候选清单才提供筛选框。
- **筛选不是模型发现，也不是手输新增。** 筛选框回车不会把关键词加入已选；手动输入 ID 使用独立小表单，加入的只是已选草稿，不发请求、不保存启用配置。准确 ID 可多个用逗号分隔；读取本家清单仍需单独授权。
- 草稿读取不要求先保存供应商或手输一个模型 ID。清单读取和能力检查是两件事；二者均需明确授权。清单成功为空是有效结果，失败可保留现场手输。
- 草稿 Key 只在内存中使用；最终确认前不写启用配置或凭据。清空**新草稿** Key 表示撤回；编辑**已保存供应商**时留空才表示保留现有凭据。
- 地址／API／Key 改变会使原连接的候选、报告和适用性失效，需要重新核对。仅改名称不会重置原连接。
- 参数按字段采用实测／人工／本渠道信息／同 ID 模板／明确未确认的默认。跨供应商映射只是建议；最终采用需显示并确认，不冒充渠道实测。
- 自动套件目前支持 OpenAI Chat Completions／Responses：每模型 8 次请求，选图片后 9 次，每次最多 64 输出 token。每次授权最多检查 3 个受支持模型、27 次请求；其余明确未测试，不自动续批。鉴权每模型最多 10 秒，套件每模型最多 90 秒，无重试。价格与输入 token 数未知，不能承诺金额上限。
- 只发送固定合成样例，不发送当前对话或用户文件。图片样例不证明普遍视觉能力；接受推理参数不证明内部执行；短请求不证明最大窗口。
- Esc 停止检查并看部分报告；Ctrl+C 结束任务。取消／超时后不开始后续请求，迟到结果不复活任务。记录失败会说明，不明文降级。
- 已启用模型也可从对象发起完整检查。查看／完成报告不修改启用配置；应用参数需独立差异确认。只读模型不能应用修改。
- 映射保留 off/minimal/low/medium/high/xhigh/max。Pi 默认（未配置）、显式空映射、`null` 不支持、字面空值彼此独立；`=` 前缀用于转义。已有映射重置为 Pi 默认也通过明确差异保存，不误删未知字段。

## 原生模型的本地参数

选择 `openai-codex` 等原生／扩展聊天模型，使用同一个 **编辑 [2]** 入口：

- 只开放**上下文窗口、输出上限**。当前生效值、目录参考和本地覆盖分开说明；无法可靠取得账户／动态目录的基础值时显示未知，不猜值。
- 输入框只带入已明确设置的本地覆盖；**留空恢复该字段的继承**。“重置为继承”清除这两项覆盖，而不是把某次目录值写死；其他手工覆盖不删。
- 查看差异后，另一次确认才保存到已验证 profile 的 `models.json` → `providers[渠道].modelOverrides[准确ID]`。取消、无变化不保存；不替换原生模型目录。
- 名称、推理／输入能力、映射、OAuth、Key、连接地址与协议仍受原有保护。虚拟路由模型不开放无效覆盖；未知 SDK／存储绑定继续只读。
- 仅调整 Pi 的本地预算，不增加服务端真实能力，也不会还原已压缩的历史；设得过大仍可能超限。不自动发起联网或付费能力测试。
- 保存后离线刷新；若该同 ID 模型仍是当前模型，更新当前对象的元数据，不切回期间另选的模型，不改全局默认。刷新失败明确说明已保存状态。

## 保存、恢复与凭据

- 直接 Key 与 Pi `/login` 共用 **`auth.json`**；该文件是 **0600 权限的明文文件**，不是额外加密凭据库。`models.json` 不新增 Key。字面 `$`／前导 `!` 按 Pi 配置语法转义，保存后解析结果不变；不执行粘贴内容来验证。
- 已有 OAuth／非 API Key 凭据不会被覆盖，其他供应商及未知 API-key 元数据保留。没有额外主密码、解锁任务或并行活动 Key 库。
- 供应商配置与凭据使用协调提交、原生兼容租约、版本检查和受保护的待恢复记录。**不是跨文件原子事务**。失败区分未提交／已回退／待恢复／已保存但刷新失败；不会假装都没写入再让你重复添加。
- 出现待恢复或无法核对的状态时，Hibiki 的相关写入、切换和读取／探测入口拒绝继续，必须先明确恢复；不盲目覆盖外部登录变化。
- 为避免本窗口旧模型地址与新 Key 混用，**当前供应商的地址／API／Key 变更拒绝保存，须先切换到其他供应商**；只改名称可保存。当前模型的参数保存会刷新仍然是当前的同 ID 对象，不覆盖期间发生的其他模型选择。
- 这不是对所有进程的全局请求锁：Hibiki 不能冻结／重绑定其他已开 Pi、其他插件或直接编辑配置的进程。不要把本地协调和当前窗口保护理解成跨窗口绝对保证。
- 移除会归档，不提供永久删除。影响当前／默认时，先选择并确认替代，再单独确认移除。撤销／恢复不自动切当前或默认；冲突不覆盖，旧版材料不自动迁移／删除。

## 平台与未完成能力

- 受保护的归档、记录和管理写入依赖 Windows DPAPI，已有 WSL 原生合成测试。Linux／macOS 保护后端未实现；不可用就拒绝相关操作。原生 Windows 尚未完成整套插件验收。
- 路径来自已核对的宿主存储绑定，包含 `PI_CODING_AGENT_DIR` profile；未知 SDK 绑定仅查看／切换，不回退写 `HOME/.pi/agent`。Ultrafast 配置也只读取该已确认 profile 的 `pi-hibiki.json`。
- 原生凭据租约有版本／长暂停方面的上游限制；不存在绝对文件系统 CAS 或恶意同用户隔离。旧非空自造锁不自动按时间删除；先备份、核对所有者并单独处理，不要盲删。
- 历史报告按连接、协议、模型和凭据代次复核，默认有效期一小时。报告保存、本渠道参考同步、启用配置应用是不同动作。
- 可配置 AI 辅助分析／自动同步策略、完整逐字段历史比较／回退界面尚未实现；受保护事件记录不等于已完成这些产品能力。其他协议的能力套件明确未测试。
- 归档绑定账户；只复制密文不保证换机恢复。异常终止可留下待恢复事务或安全锁，不能以忽略／明文重写的方式绕过。

## Fast

`/fast [on|off|ultrafast|status|check]` 保留原会话／分支策略。首页 Fast 只作用于适用的**当前模型**，不冒充光标候选能力；`status/check` 只观察，不发探针。请求档位、上游回显、实际加速和计费分别看待。

Ultrafast 默认关闭，在已确认 profile 的 `pi-hibiki.json` 中显式启用：

```json
{ "fast": { "enableUltrafast": false } }
```

## 开发与验证

直接编辑 TypeScript 源码，使用已安装 Pi／TypeScript：

```sh
export HIBIKI_PI_ROOT=/path/to/pi-coding-agent
export HIBIKI_TYPESCRIPT_ROOT=/path/to/typescript
npm run verify
```

验证使用临时合成 profile 和网络／文件误操作守卫，不使用真实凭据或真实供应商，不自动安装依赖。完整套件的原生保护测试需要 WSL＋Windows DPAPI。实际 Pi PTY 路由、PNG 字符栅格预览、原生 WezTerm 观感与作者验收分别记录，互不冒充。守卫不是 OS 沙箱。
